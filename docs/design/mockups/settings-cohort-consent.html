Counts and ratios only — no names, routes, tags or text can exist in the schema (an executable self-audit pins every field, the frame.py pattern). Figures are passthrough of audited numbers — no new money math, so no pricing-golden impact. Two exports of the same DB are byte-identical (deterministic sort, pure read).

Absence rules · everywhere else
No customer surface changes beyond the one Settings card: no banner, no dashboard mention, no countdown anywhere customer-visible. A workspace that never opts in appears NOWHERE in any export — absence from the file is the default state, not an empty row. The admin endpoint is token-gated like every /admin route; there is no API/SDK surface for this export (R-SCOPE-STOP — the factory pulls from /admin, nothing else).

Kit composition: the Settings card is the shipped kit.surface_open + the checkbox-consent idiom Peer benchmarks already uses — kit tones only, no new colors on the card (ux f.3: AA holds because only already-audited kit tokens appear at wiring). The admin row wires into the shipped BARE admin panel (header-token curl actions, no kit, no buttons) — the styled button here is illustrative; the wired affordance is the state row + the documented GET /admin/cohort-export.json action line, matching every other admin action. Green appears only on the founder's “live” pill (a state fact, not a money claim — same tone the admin digest already uses for LIVE rungs). R-DESIGN-ADDENDUM delight: NONE claimed — this is a consent control and an ops row; the designed care is the consent copy telling the whole truth in one breath (what leaves, what never can, when nothing leaves at all) so the decision needs no docs page. “Cohort learning” is glossed in the card title at first use; “k-anonymity” is glossed inline (“ten or more opted-in workspaces”).
