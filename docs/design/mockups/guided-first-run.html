You're paying full price for prompts you send again and again

$0.25 / month
What's happening

A few of your routes send the same large block of text at the start of every request — the same instructions or context, over and over.

Why it's costing you

Your provider can "cache" that repeated block and charge you a fraction to reuse it. Right now that caching isn't turned on for these calls, so you pay full price for the same text every single time.

What to do

Turn on prompt caching for the repeated part — your provider calls it "cache control" or "prompt caching." You mark the stable opening of the prompt once, and repeat calls read it instead of re-sending it.

How you'll know it worked

Your next audit shows cache reads on those calls and this finding shrinks or disappears — the saving shows up in your headline.

How we detected this (technical)

D2 · d2_missing_cache · conservative floor. Flagged when the same prompt prefix repeated ≥ 5 times at ≥ 1,024 tokens with no cache reads; the estimate is reduced by a haircut for prefix drift. Evidence: token counts, timestamps and hashes only — no prompt text is ever stored.

Design decisions & laws honored

Honesty is the whole point (data-coherence lesson, 2026-07-24). The last slice closed a gap where historical figures read as live. The preview reopens that risk — sample numbers next to a real, signed-in user — so it is fenced hard: a dashed amber (--estimate) frame, a diagonal wash, a persistent ◆ SAMPLE — NOT YOUR DATA badge, an explicit "nothing on this card is yours," and it uses the estimate palette, never the earned verified green. It cannot be mistaken for the user's own money.
  • No invented numbers (extends the no-invented-numbers law). The preview is the FR-16 /sample data — build_sample() → real ingest→price→detect→assemble. Figures shown here are the actual engine output ($0.89/mo · 11.7% · the five plain-English findings). Placeholders would be a lie; these aren't.
  • X-04 (no LLM narrative) untouched. Every word is deterministic template + registry plain phrasing; no generated prose.
  • FR-22 (no prompt text). The sample findings carry counts and plain titles only, same as any finding row.
  • Reachability (R-VERTICAL). This IS the post-sign-in landing for a new user — reachable by definition. Both CTAs (/upload, /sources) already exist and work.
  • Vanishes on first real audit. Gated on audit_clarity.state == "none" (no completed audit in the active workspace). One completed audit → this surface is replaced by the live widget grid; the preview never sits beside real figures.
  • Absorbs, doesn't duplicate. The 3-step guided path is the connect→audit→report arc; the standalone getting-started checklist is suppressed in this pure first-run state (the hero IS the guided path) and reappears afterward for the review→apply→verify steps that only make sense once data exists.
  • Honest framing. The committed sample is small ($0.89/mo); the preview pairs the dollar hero with %-of-spend and the ranked plain-English findings — the parts that communicate value and scale — and says plainly the dollars scale with real traffic.
  • No dead controls (shell rule). Steps 2 and 3 are "what happens next," not buttons; only step 1 is actionable.
  • Money is the most-weighted figure (R-DESIGN money law). The $0.89/mo dollar is the 34px heavy-sans display numeral (serif is retired, R-LOOK-FINAL); the 11.7% reads as a supporting chip; the findings table composes the real .ledger so its Monthly column matches the shipped findings table. Dollars lead as the hero.
  • The one designed delight. The "YOU ARE HERE" marker on step 1 of the guided path: the whole four-stage journey is laid out, and exactly one step is lit as the user's current position — the same "you can see the whole loop, and where you are in it" grammar as the pipeline ribbon. One delight, not a carnival.
  • Accessibility (R-DESIGN-ADDENDUM). AA verified: --estimate on --estimate-bg ≈ 5.2:1, --ink-soft on --ground ≈ 6.5:1. No motion or animation on this surface, so nothing to gate for reduced-motion.
