# Architecture

One FastAPI monolith, one Postgres, one reverse proxy, one cron sidecar. At
this product's scale, a monolith with enforced internal boundaries beats a
service mesh on every axis that matters: deploy time, debuggability, and the
attack surface your logs are exposed to. <!-- src: docs/02-HLD.md §1 -->

## The boundaries that matter

**The engine is sealed.** `services/rules` and `services/pricing` import no
network and no LLM libraries — an AST-walking import-guard test fails the
build on violation. Everything that touches the outside world (web, mail,
payments) lives outside the engine. <!-- src: NFR-01; ADR guard -->

**Numbers are assembled once.** `report/model.py` is the only place report
numbers are computed; the JSON, web, and PDF renderers serialize that model
and never recompute. A drift between your PDF and your JSON is structurally
impossible. <!-- src: ADR-4; T-REP-01 -->

**Routes never touch the ORM directly.** Persistence goes through repository
helpers, keeping transaction boundaries auditable.
<!-- src: architect G4 note, applied at D8 -->

**Migrations are additive-only** in v1 — rollback is a code rollback, never a
schema down-migration with your data in it. <!-- src: runbook §2 -->

## Decision records

The architecture decisions (monolith over services, single report assembly,
signed-URL reports over per-report auth, BackgroundTasks over a queue in v1,
additive-only migrations) are kept as ADRs in the internal spec kit and
enforced by the architecture gate at review milestones — deviations must be
disclosed and accepted, or the gate fails. <!-- src: docs/02 ADR-1..7 -->
