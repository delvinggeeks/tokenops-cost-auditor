Grant us read-only eyes on your metrics — Azure enforces it

Azure OpenAI publishes token and request counts as Azure Monitor metrics on your resource. We read those metrics with a service principal you create, holding exactly one role: Monitoring Reader, on exactly one resource. Five minutes in the portal:

  1. Microsoft Entra ID → App registrations → New registration. Name it (e.g. tokenops-cost-auditor-reader), register.
  2. Copy the Directory (tenant) ID and Application (client) ID from the overview page.
  3. Certificates & secrets → New client secret. Give it an expiry; copy the secret Value now (Azure shows it once).
  4. Open your Azure OpenAI resource → Access control (IAM) → Add role assignment → Monitoring Reader → select your new app.
  5. On the resource's Properties page, copy the Resource ID (starts /subscriptions/…).

This is an Entra ID service principal with the Monitoring Reader role. Anyone with Owner or User Access Administrator on the resource can grant it.

The principal can

read monitoring metrics for the one resource you granted — token counts, request counts, by model and deployment.

It cannot

call your models, read prompts or completions, or touch any other resource — Azure's own RBAC enforces this, not our promise.

Set an expiry on the secret when you create it, and revoke here whenever you like — revoking deletes our copy immediately.

What we read

We read: Azure Monitor's usage metrics — how many calls, which models, and how many tokens; the same counts behind your bill.

We never read: your prompts, your completions, or your customers' data. The role we hold cannot call your models.

What Azure doesn't expose: cached-token counts for standard deployments. Detectors that need cache visibility say "not observable on Azure" in your report — an honest label, never a guessed zero.
