Grant us read-only eyes on your metrics — IAM enforces it

Bedrock publishes token and request counts as CloudWatch metrics. We read them with an IAM access key that holds exactly one permission set: CloudWatch read-only. Three minutes in the console:

  1. IAM → Users → Create user. Name it (e.g. tokenops-cost-auditor-reader); no console access needed.
  2. Attach policies directly → CloudWatchReadOnlyAccess. (Or an inline policy allowing only cloudwatch:GetMetricData and cloudwatch:ListMetrics — tighter still.)
  3. Security credentials → Create access key (choose "Third-party service"). Copy the Access key ID and the Secret access key now — AWS shows the secret once.
  4. Note the AWS region your Bedrock workloads run in (e.g. us-east-1) — metrics live in the region.

This is an IAM access key with CloudWatch read-only permissions. Anyone with IAM user-management rights can create it.

The key can

read CloudWatch metrics in your account — token counts, request counts, by model.

It cannot

invoke your models, read prompts or completions, or change anything — AWS IAM enforces this, not our promise.

Rotate or delete the key in IAM whenever you like; revoking here deletes our copy immediately.
